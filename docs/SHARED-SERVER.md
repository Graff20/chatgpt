# Цех 0.6.0 — первый запуск общей системы

Это пилот: исходные данные сохраняются, но перенос и первые отгрузки проверяются на копии. Реальная установка Windows и проверка APK на вашем смартфоне выполняются вместе с владельцем устройств. У нас нет прямого доступа к вашим компьютерам.

## Что подготовлено

- Общая SQLite-база на одном серверном ПК. Только сервер открывает файл базы; клиенты используют API. Файл базы не размещать в общей сетевой папке, OneDrive или на смартфонах.
- Отдельный Windows-клиент CehClientSetup.exe (нативное окно WebView2, Python на рабочем ПК не нужен).
- Android 11+ ru.ceh.mobile: устанавливаемый APK, встроенное окно работы, печать, загрузка документов и настройка адреса сервера. Проверены сборка и подпись; запуск на физическом Android ещё нужно проверить.
- Три роли и личные входы. Менеджер видит своих клиентов; производство — производственные операции; админ — полный учёт, сотрудников, задачи и контроль результатов.
- Задачи руководителя, графики звонков/визитов (включая период в неделях), работа с просроченными долгами, история переносов, результат и проверка директором.
- Фото накладной/чека можно приложить к приёмке с камеры или из галереи. Оно сохраняется атомарно вместе с документом в общей базе и входит в резервную копию; доступно производству и админу. Строки и цены проверяются и вводятся вручную.
- Перепродажа: отдельный способ поступления готового товара. Приёмка от поставщика без ТТК и зарплаты; дефицит отдельно от производства; аналитика по происхождению.

На первом запуске нет автоматического распознавания накладных, подтверждения телефонных соединений, GPS-контроля, системных push-уведомлений или проведения без связи. Заказ можно сохранить черновиком на устройстве при открытом интерфейсе. Для холодного запуска приложения нужен сервер. Производственные документы проводятся только при связи. Изображения и документы не отправляются внешним сервисам распознавания.

## 1. Сохранить базу на рабочем ПК

1. В существующем Цех: «База и настройки → Скачать резервную копию».
2. Отдельно скопировать всю прежнюю папку data. Исходную рабочую папку не заменять.
3. Согласовать время переноса: после финальной копии не вести учёт параллельно в прежней и новой базе.
4. Перенести скачанный файл .sqlite3 на круглосуточный ПК с SSD и 16 ГБ памяти. Не копировать открытый ceh.sqlite3 без WAL: нужен файл резервной копии из интерфейса.

Версия 0.6.0 мигрирует схемы 1–5 последовательно, для перехода 5 → 6 сохраняет before-v6-…sqlite3. Прежние позиции получают способ «Собственное производство». Цены счетов, количества, партии и финансовые суммы миграцией не пересоздаются. Перепродажу задавайте отдельным карточкам; менять источник уже использованной позиции запрещено.

## 2. Получить Windows-сборки

В GitHub → Graff20/chatgpt → Actions → **Windows clients and server** → успешный запуск:

- `Ceh-Server-Windows` — сервер и установочные сценарии;
- `Ceh-Windows-Installer` — установщик рабочих мест.

Сборки создаются на Windows в GitHub Actions. Пилотный APK находится также в downloads исходников. Не заменяйте отсутствие успешной сборки ручным копированием незавершённого dist.

Windows-установщик пока не подписан коммерческим сертификатом издателя. Если Windows предупреждает о неизвестном издателе, сначала сверяем источник и контрольную сумму, а не отключаем защиту компьютера.

## 3. Установить сервер

1. Распаковать полный `Ceh-Server-Windows`; внутри должны быть dist/CehServer и windows.
2. Запустить `windows/install-server.cmd`; потребуется подтверждение администратора Windows.
3. Выбрать скачанную резервную копию в диалоге. Не указывать папку — выбирается файл .sqlite3.
4. В открывшейся консоли создать логин и пароль администратора. Пароль не короче 12 символов; при вводе символы могут не показываться. Не присылайте пароль в чат.
5. Сервер открывает локальную страницу входа. Войти и проверить каталог, остатки, партии, документы, задолженность и зарплату против рабочей программы. При расхождениях не начинать рабочий учёт.

Файлы сервера — ProgramData/CehServer, база — ProgramData/CehData/ceh.sqlite3, журнал — ProgramData/CehData/logs/server.log. Файлы базы доступны SYSTEM и администраторам Windows. Сервер стартует задачей планировщика Windows `CehServer` при включении компьютера, даже без открытого браузера. Отключите сон; контролируйте питание и интернет. Это задача автозапуска, а не отдельная служба в Services.msc.

Если используются исходники с Python 3.11+ вместо сборки:

```
python manage.py init-admin --data D:\CehData
python app.py --secure --data D:\CehData --host 127.0.0.1 --port 8765
```

В D:\CehData должна быть именно копия ceh.sqlite3. При существующих аккаунтах вход обязателен даже без --secure. Обычный старый локальный режим сохраняется только для базы без аккаунтов.

## 4. Удалённое подключение

Порт 8765 остаётся на 127.0.0.1. Не пробрасывать его на роутере и не открывать файл базы в интернет.

Нужен отдельный шаг настройки VPN и HTTPS. Варианты:

- VPN с HTTPS-прокси, например Tailscale + Serve. Перед выбором проверяем актуальные условия коммерческого использования и стоимость; бесплатный тариф для восьми сотрудников не обещан. Используем отдельные устройства/ключи, без передачи одного пароля всем сотрудникам. Funnel (публикация в открытый интернет) не нужен.
- WireGuard на своём оборудовании, если провайдер предоставляет доступный внешний IP и роутер/сервер поддерживает нужный маршрут. HTTPS с доверенным сертификатом настраивается отдельно. При CGNAT может потребоваться внешний адрес или промежуточный узел.

Пример Serve после установки и регистрации серверного ПК в вашей VPN: `tailscale serve --bg http://127.0.0.1:8765`. Доступ ограничивается вашей VPN-политикой; каждому устройству нужен допуск. В параметрах задачи CehServer добавить `--public-url https://имя-сервера.ваша-сеть.ts.net` и перезапустить задачу. Не игнорировать ошибки сертификата в клиентах.

На сервере и рабочих местах нужны действующие обновления безопасности ОС. Для Windows 10 нужно проверить поддержку/ESU или возможность обновления ОС. Перед подключением смартфонов проверим процессор, разрядность Windows, доступность VPN и получившийся HTTPS-адрес. Эти действия ещё не выполнены на ваших устройствах.

## 5. Первые пользователи и роли

Войти администратором → «Управление работой» → «Сотрудники».

- Создать личные логины и роли: Торговля, Производство, Админ (можно совмещать).
- В «Клиентах» назначить старых клиентов менеджерам; существующие имена в старых документах не считаются подтверждёнными учётными записями и не назначаются автоматически.
- В карточке настроить прайс, отсрочку, лимит, разрешение отгрузки. Новый клиент менеджера появляется сразу, заказ создать можно; первую отгрузку нового клиента подтверждает администратор.
- Настроить графики контактов, поручения и обязательную проверку результатов. Запланированные задачи материализуются на 14 дней вперёд; история прошлых дней сохраняется.
- При передаче клиента выбрать перенос незавершённых задач и графиков. Лимит 0 в старом учёте означает отсутствие лимита; это правило сохранено. Менеджер не может сам увеличивать кредитные условия.

## 6. Установить клиенты

**Windows:** запустить CehClientSetup.exe. При первом открытии ввести подготовленный HTTPS-адрес. Далее личный логин/пароль. Пункт настройки подключения в меню «Пуск» позволяет сменить сервер. Учётные данные в connection.json не хранятся.

**Android:** установить downloads/ceh-android-pilot.apk. Android попросит разрешить установку из выбранного источника. Открыть «Цех», ввести тот же HTTPS-адрес, войти личным логином. Вход сохраняется защищённой cookie сессии на 12 часов. При истечении сессии повторный вход не закрывает открытую форму; повторная отправка использует прежний идентификатор операции. Подпись APK проверена средствами Android SDK; работу с реальным устройством проверяем отдельно. Первым подключаем один смартфон, потом остальных.

## 7. Обновления

- Интерфейс и бизнес-логика находятся на сервере. Обычный патч интерфейса подхватывается клиентом после обновления экрана, без установки APK/EXE заново.
- Для изменения нативных функций выпускается новый подписанный APK с **тем же ключом и package ru.ceh.mobile**, увеличенным versionCode. Приложение проверяет manifest `/api/client-version`, скачивает APK, сверяет SHA-256 и открывает штатный установщик Android. Тихая установка не выполняется.
- Windows-клиент проверяет версию при запуске, с согласия скачивает HTTPS-установщик, проверяет SHA-256 и запускает его. Настройки адреса остаются в LocalAppData/CehClient.
- Для публикации готовых пакетов используется `windows/publish-updates.ps1 -PublicUrl https://ваш-сервер -AndroidFile <APK> -WindowsFile <EXE>`. Рядом с пакетами должны быть их `.json` из сборки; сценарий проверяет SHA-256, копирует только программы в папку updates и создаёт manifest. Файлы доступны по известным адресам `/downloads/…` и не содержат базу или ключи. Один номер версии нельзя заменить другим файлом.
- Администратор публикует `updates.json` в папке базы. Формат — docs/updates.example.json. Это файл версий/URL/контрольных сумм, без паролей. `minimum` повышается только при обязательном обновлении. Для обычного патча клиента минимум сохраняем прежним.
- Сервер обновляется централизованно через `windows/update-server.ps1` из новой полной сборки. Сценарий включает обслуживание, делает согласованную SQLite-копию **с учётом WAL**, останавливает сервер, сохраняет старые файлы, заменяет программу и проверяет запуск. При сбое режим обслуживания остаётся включённым, база не стирается.
- Откат после миграции: остановить задачу, восстановить согласованную пару старой программы и копии базы из updates/<дата>, отдельно сохранить текущие файлы перед заменой. Не запускать старую программу поверх новой схемы и не объединять две базы вручную.

**Ключ подписи пилота:** пробный APK подписан отдельным ключом, который хранится вне репозитория. В публичном GitHub нет ни ключа, ни пароля. До рабочего распространения нужно создать/передать владельцу постоянный приватный ключ и сохранить две защищённые копии. Если рабочий ключ отличается от пилотного, пилот придётся удалить перед установкой рабочей версии; общая база от этого не исчезнет, но локальные черновики нужно отправить/сохранить заранее. Не обещаем бессрочные обновления пилота без резервной копии его ключа.

Для самостоятельной сборки: Java 17, Android SDK platform 35 и build-tools 35.0.0; `python scripts/build_android.py --sdk <SDK> --keystore <приватный ключ> --password-file <приватный файл пароля>`. Постоянный ключ создаётся локально scripts/create_signing_key.py. В GitHub Actions рабочая Android-сборка использует секреты владельца репозитория; приватные файлы в артефакты не включаются.

## 8. Резервное копирование

Локальные SQLite-копии создаются автоматически при запуске за день и перед миграцией. Для ежедневной копии **вне серверного ПК** настроить запуск windows/backup-server.ps1 с параметром Destination на отдельном носителе/защищённом хранилище. Сценарий использует SQLite backup API, хранит свои ежедневные копии 30 дней и не очищает другие файлы. Внешнее хранилище и расписание ещё нужно настроить на ваших устройствах. Копия на другом разделе того же SSD не заменяет внешнюю копию.

Фотографии увеличивают размер базы. Для копий больше лимита загрузки интерфейса (48 МБ) восстановление выполняется локально при остановленном сервере.

Восстановление сетевой базы через интерфейс требует копии с аккаунтами; старая локальная копия переносится при остановленном сервере с созданием администратора. Пароли можно сбросить только локальной утилитой CehAdmin reset-password --data <папка базы>; это не открытый HTTP-метод.
